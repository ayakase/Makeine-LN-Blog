# Makeine LN Blog

A blog/web app for the Makeine light novel series. Built with a **SvelteKit** frontend and a **Hono** API backend deployed on **Cloudflare Workers** with a **D1** (SQLite) database.

---

## Tech Stack

| Layer    | Technology                                              |
| -------- | ------------------------------------------------------- |
| Frontend | SvelteKit 2, Svelte 5, Tailwind CSS v4, DaisyUI 5      |
| Backend  | Hono, Cloudflare Workers                                |
| Database | Cloudflare D1 (SQLite) via Drizzle ORM                  |
| Tooling  | Vite 7, TypeScript 5, Wrangler 4, Drizzle Kit           |

## Getting Started

### 1. Clone & install dependencies

```bash
git clone <repo-url> && cd Makeine-LN-Blog

# Install both client and server deps
cd client && npm install && cd ..
cd server && npm install && cd ..
```

### 2. Configure environment

#### Server (`server/`)

Wrangler config lives in `server/wrangler.jsonc`. The D1 database binding is already defined there:

```jsonc
"d1_databases": [
  {
    "binding": "makeine",          // accessed as c.env.makeine in Hono
    "database_name": "makeine",
    "database_id": "<your-database-id>"
  }
]
```

If you need environment variables (API keys, secrets, etc.), create a `.dev.vars` file inside `server/`:

```env
# server/.dev.vars
MY_SECRET=super-secret-value
```

> `.dev.vars` is gitignored and is the Wrangler equivalent of `.env` for local development.

#### Client (`client/`)

No special env config is needed by default. If you later need public env vars, use SvelteKit's `$env/static/public` with a `PUBLIC_` prefix in a `.env` file inside `client/`.

### 3. Run database migrations

```bash
# Apply migrations to your LOCAL D1 dev database
cd server
npx wrangler d1 migrations apply makeine --local

# Apply migrations to REMOTE D1 (production)
npx wrangler d1 migrations apply makeine --remote
```

### 4. Run in development

Open **two terminals**:

```bash
# Terminal 1 — Frontend (http://localhost:5173)
cd client
npm run dev

# Terminal 2 — Backend (http://localhost:8787)
cd server
npm run dev
```

Both use `npm run dev`. The client runs Vite's dev server, the server runs `wrangler dev`.

## Backend Architecture

### Framework — Hono

[Hono](https://hono.dev) is a lightweight, ultrafast web framework designed for edge runtimes. The app entrypoint is `server/src/index.ts`:

```ts
const app = new Hono()
app.route('/admin', admin)    // mount route groups
export default app
```

### Routing

Routes are organized as separate modules in `server/src/routes/` and mounted onto the main app. Example: `admin.ts` handles `/admin/*` endpoints.

| Method | Endpoint       | Description        |
| ------ | -------------- | ------------------ |
| GET    | `/admin`       | Health check       |
| GET    | `/admin/users` | List all users     |
| POST   | `/admin/users` | Create a new user  |

### Database — Cloudflare D1 + Drizzle ORM

- **D1** is Cloudflare's serverless SQLite database, bound to the Worker via `wrangler.jsonc`.
- **Drizzle ORM** provides type-safe queries and schema management.
- Schema is defined in `server/src/db/schema.ts`.
- Migrations live in `server/drizzle/` and are generated by Drizzle Kit.

#### Generating new migrations

When you modify the schema:

```bash
cd server
npx drizzle-kit generate
```

Then apply them (see [Run database migrations](#3-run-database-migrations)).

## Deployment

### Server → Cloudflare Workers

```bash
cd server
npm run deploy
# runs: wrangler deploy --minify
```

This deploys the Hono API as a Cloudflare Worker. Make sure you're logged in via `wrangler login` first.

Before deploying, ensure your **remote** D1 database has the latest migrations applied:

```bash
npx wrangler d1 migrations apply makeine --remote
```

### Client → Any static/edge host

The client uses `@sveltejs/adapter-auto`, which auto-detects the deploy target. Popular options:

| Platform         | Adapter                        | Notes                                       |
| ---------------- | ------------------------------ | ------------------------------------------- |
| Cloudflare Pages | `@sveltejs/adapter-cloudflare` | Pairs nicely with the Workers backend       |
| Vercel           | `@sveltejs/adapter-vercel`     | Zero-config                                 |
| Netlify          | `@sveltejs/adapter-netlify`    | Zero-config                                 |
| Static / GitHub Pages | `@sveltejs/adapter-static` | Fully static export                        |

To build for production:

```bash
cd client
npm run build
```

> **Tip:** If deploying to Cloudflare Pages, install `@sveltejs/adapter-cloudflare` and update `svelte.config.js` to use it. Then connect the repo to Pages in the Cloudflare dashboard — it will build and deploy on push.
